# 📚 База знаний проекта (PROJECT_KNOWLEDGE.md)

## 1. Описание проекта
**Discord Tickets Bot** — высокопроизводительный Discord-бот для конвертации билетов Apple Wallet (`.pkpass`) в единый многостраничный Pixel-Perfect PDF-документ, визуально на 100% идентичный отображению билета типа `eventTicket` на экране iPhone.

---

## 2. Архитектура и стек технологий

### Стек:
- **Python 3.11+**
- **discord.py (>= 2.3.2)** — взаимодействие с Discord API Gateway (события сообщений, вложений, реакций).
- **Playwright (>= 1.42.0)** — headless Chromium для точного рендеринга HTML в PDF с сохранением векторных элементов, шрифтов и фона.
- **Jinja2 (>= 3.1.3)** — шаблонизатор HTML-разметки билетов (`templates/ticket_sheet.html`).
- **segno (>= 1.6.1)** — генерация полноразмерных стандартных QR-кодов (ISO/IEC 18004) без Micro QR в SVG Data URI.
- **python-barcode (>= 0.15.1)** — генерация линейных 1D штрихкодов (`Code 128`) для билетов Etix и других билетных операторов.
- **Pillow (>= 10.2.0)** — вспомогательная обработка изображений.
- **python-dotenv (>= 1.0.1)** — загрузка переменных окружения (`DISCORD_BOT_TOKEN`).
- **pytest, pytest-asyncio** — автоматизированное тестирование модулей парсинга, рендеринга и бизнес-правил бота.

## 3. Терминология и стандарты

- **`.pkpass` (Apple PassKit Package):** ZIP-архив, содержащий манифест, подпись, файл спецификации `pass.json`, изображения (`logo.png`, `strip.png`, `icon.png`) и папки локализации (`*.lproj/pass.strings`).
- **`pass.json`:** Главный конфигурационный файл билета по стандарту Apple Wallet. Содержит структуру полей (`headerFields`, `primaryFields`, `secondaryFields`, `auxiliaryFields`), цвета фона и текста, информацию о штрихкодах и организаторе.
- **`eventTicket`:** Стандартный тип пропуска Apple Wallet для концертов, театров, спортивных мероприятий.
- **Notch:** Верхний полукруглый/скругленный вырез по центру карточки билета Apple Wallet.
- **Pixel-Perfect PDF:** Выходной документ формата A4 portrait на чистом белом фоне (`#FFFFFF`) для экономии краски/тонера при печати. Каждый билет размещается строго на отдельной странице, повторяя цвета, шрифты Apple (`-apple-system`, `SF Pro Display`, `SF Pro Text`), пропорции карточки (375px ширина, радиус скругления 18px), верхний вырез (Notch) и векторный штрих-код.
- **Standard QR vs Micro QR:** Apple Wallet использует исключительно полноразмерный стандартный QR-код (`ISO/IEC 18004`) с 3 угловыми метками (`Finder Patterns`). Генерация Micro QR недопустима из-за риска несканирования на турникетах площадок.

## 4. Бизнес-правила и логика работы бота

1. **Входные данные:**
   - Пользователь отправляет сообщение с файлами `.pkpass` боту в ЛС или в канал (с упоминанием бота или напрямую в зависимости от настроек).
2. **Валидация количества файлов:**
   - **0 файлов `.pkpass`:** При обращении в ЛС или теге бота отправляется подсказка с правилами использования.
   - **> 10 файлов:** Запрос отклоняется с сообщением: `❌ Ошибка: Максимальное количество билетов для единовременной обработки — 10 шт.`
   - **От 1 до 10 файлов:** Запрос принимается в обработку.
3. **UX и индикация статуса:**
   - Ставится реакция `⏳` на сообщение пользователя.
   - Запускается статус `typing...` в канале.
   - При успешной генерации реакция меняется на `✅`.
   - При ошибке ставится реакция `❌` и отправляется детальное описание ошибки.
4. **Безопасность и хранение:**
   - Обработка файлов и архивов происходит **строго в оперативной памяти** (`io.BytesIO`). Никаких временных файлов билетов на диск не записывается.
5. **Именование файлов:**
   - Имя сгенерированного PDF формируется на основе даты мероприятия первого билета: `tickets_event_YYYY-MM-DD.pdf`.

## 5. Особенности реализации и критические нюансы

1. **Приоритет локального времени над `relevantDate`:**
   - В стандарте Apple Wallet поле `relevantDate` используется для активации на экране блокировки и передается в UTC.
   - Основным источником истины для даты и времени события являются поля `headerFields`. Они отображают локальное время площадки.
2. **Локализация `pass.strings`:**
   - Поддерживает UTF-8, UTF-16LE, UTF-16BE.
   - Экранирования `\uXXXX` обрабатываются без искажения кириллицы (см. `_clean_apple_string` в `parser.py`).
3. **Генерация штрих-кодов:**
   - Для QR-кодов используется `segno.make_qr(..., error="M")`.
   - Для 1D штрихкодов `PKBarcodeFormatCode128` используется `python-barcode` со шрифтом SVGWriter.
   - Оба типа кодируются в `data:image/svg+xml;base64,...` для сохранения идеальной четкости при печати.
4. **Рендеринг через Playwright:**
   - `device_scale_factor: 2` (Retina-качество).
   - `print_background: True` для точной заливки фона карточки и страницы.
   - `prefer_css_page_size: True` для соблюдения разметки CSS `@page`.
